## 已进入当前实现的结论

### API、认证与隐私

- WBI、QR 登录状态和 Cookie 传播继续采用 endpoint 级精确边界；游客、图片、媒体 CDN 和
  loopback 请求不携带认证授权器。
- V1 不引入 refresh token。认证材料只在 `BiliAuth` 的短生命周期内存和 Keychain 中存在。
- 生产远端 transport 使用用途专属的 ephemeral、禁 Cookie、禁 cache、拒绝重定向配置；
  真实远端 probe 已移出 GitHub-hosted CI。
- loopback 仅绑定 `127.0.0.1`，校验 token、path 和严格 Host；取消和 stop 都有清理所有权。
- 诊断只输出安全投影，不读取或导出原始 AVPlayer access/error log 中的 URI、服务器等字段。

### 播放与媒体

- 自动画质由同一 `AVPlayerItem` 内的原生 ABR 完成，不提供手动档位，也不自行设置首档、
  peak cap 或额外 buffer 策略。
- representation 固定到准备成功的单一来源；后续 Range 不跨 CDN 对象拼接。
- loopback 对 single closed/open/suffix Range 返回正确的 `206`，不可满足范围返回 `416`；
  非法或不支持的 Range 不向上游扩散。
- 恢复 AVPlayer 默认等待行为，并以 item identity 隔离持续失败、旧通知和清理。
- 弹幕 segment 失败在当前 session 内记忆；重建 session 后才允许重新请求，避免 timeline
  更新造成请求风暴。
- 空白弹幕在 trim 后跳过，颜色在 decoder 边界规范为 24-bit RGB。

### 状态、UI 与资源所有权

- App 使用稳定的单一 `AppWindowOwner`；异步结果同时受 cancellation、identity 和 generation
  约束。
- 每个 tab 使用独立导航 path；系统 Back 通过 coordinator 的唯一 reconciliation owner
  停止播放。切换 tab 不允许隐藏栈写入当前播放目的地。
- 搜索使用原生 `.searchable`；时长格式统一使用 Foundation format style；热门和搜索工作集
  保持有界。
- observer、播放器、字幕、弹幕、loopback listener 和 owned session 均保留明确的取消、
  replacement 与 stop 清理点。
- V1 继续使用 `AsyncImage`，不新增自建图片缓存框架或通用 `URLCache` 策略。

### 架构与工程

- Application ports、11 个 library target、网络／认证／弹幕平台协议和 references clean-room
  隔离继续保留。
- 删除了零调用者的宽 `PlayerEngine` protocol 和多余 `BiliWatchHistoryService` 中间层；没有
  删除语义明确的 playback ports、events 或 Application repository port。
- hosted CI action 固定为审核过的完整 commit SHA。
- 删除了未使用的 user-selected file entitlement 和冗余 App Group；保留 App Sandbox、网络、
  Keychain access group 和 Hardened Runtime 所需配置。

## 当时取得的关键证据

- 签名 App 的 Keychain add/update/read/attributes/delete smoke 通过。
- loopback 对合法 authority、错误 token/path、异常 Host、断连和 stop 后端口关闭完成独立验证。
- 播放往返、窗口循环、受控 starvation/error、长时弹幕 scheduler、Allocations、RSS 和 lsof
  提供了定点证据。
- 原生搜索 Return/Escape、系统 Back、播放输入、全屏/PiP 和若干签名真实播放路径完成验证。
- 自动 package/app Gate 在各窄修复后通过；精确的历史测试数只属于当时提交，不应当作当前
  测试数量。

## 不能从本审计推出的结论

- 没有 Developer ID 成品、notarization、DMG、隔离属性、Gatekeeper 或真实升级安装证据。
- 当时没有真实 Intel Mac 运行证据；当前 V1 的 Universal 与 Intel Gate 由
  [`../release/README.md`](../release/README.md) 单独管理。
- 没有熟练 VoiceOver／Full Keyboard Access 全路径验收，也没有 200% 字号和完整本地化矩阵。
- Allocations/RSS 只证明受控样本未见持续累积，不等于 Memory Graph 已证明零 retain cycle，
  更不等于全产品无泄漏。
- 没有长期服务端漂移、真实 403/key 漂移、完整认证高清/4K、HEVC/AV1、多内容 switching set
  或所有 CDN 失败形态证据。
- 外部开源 checkout 只代表审计日期的 commit 快照；任何“当前实现”判断都必须重新核对远端
  官方或上游事实。

## 后续复核触发条件

只有在相应边界发生变化时才重开专项验证：认证协议或 allowlist 改动、媒体来源或 Range
实现改动、owner/lifecycle 改动、缓存策略改动、正式 Developer ID 候选产生，或准备对外承诺
Intel、辅助功能、4K/codec、升级和无泄漏时。不要恢复整套历史审计流程来代替一个窄问题的
当前验证。
