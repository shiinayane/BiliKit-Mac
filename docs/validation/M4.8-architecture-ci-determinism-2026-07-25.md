# M4.8 架构公共面与 CI 确定性验证

- 日期：2026-07-25（Asia/Tokyo）
- 环境：macOS 26.5.2 arm64、Xcode 26.6、Swift Format 6.3.0
- 分支：`codex/m4.8-architecture-ci-determinism`
- 基线：`codex/m4.7-architecture-lint-governance` 的 `f7d1c77`

## 范围

- 删除与 Application-owned `GuestContentRepository` 重复、只为 adapter 测试替身
  保持 public 的 `BiliAPIService`；
- `BiliGuestRepository` 改为私有持有具体 `BiliAPIClient`，Composition 只更新组装，
  Feature 与 Application port 不变；
- 以自制 `HTTPTransport` 和 fixture 固定 adapter 的错误映射与取消传播，不重新引入
  API 层 service protocol；
- 将 Browse、Library、Auth 与 Danmaku 中已知依赖短暂 sleep 排序的测试改为请求
  开始、释放、完成与 presentation update 的 continuation／事件闸门；
- 统一 App Gate 在 GitHub Actions 中输出 stage group、Step Summary 与实际
  `swift-format` 版本，不拆出重复 lint job。

## 独立审查

- 架构 reviewer 首轮发现一个 App 测试仍使用旧 `service:` initializer；整改后确认
  生产与测试 Swift 源码均无 `BiliAPIService` 或旧 initializer 引用，依赖方向、
  owner、公共面、Composition 和迁移完整性无 blocker。
- 架构 reviewer 将 Danmaku presentation 的 1 ms 轮询交由普通黄区审查；主 Agent
  已改为 sink update-count continuation，并移除该测试的 5 ms 排序条件。
- 普通黄区 reviewer 首轮指出观察 continuation 不响应测试取消，且 repository 发出
  completion 不等于旧 ViewModel／Session Task 已执行 generation 防线。
- 当前 revision 的用户实现确认即“开 M4.8，解决架构 improvement 以及改进 CI 工作流，
  不使用时间等待推断完成”。按红区最小契约整改后，观察 waiter 由 actor 字典统一
  注册、取消和 exactly-once resume；取消触发 sticky `releaseAll`；测试在新意图前
  snapshot 旧 Task，release 后等待其真实结束再断言。
- 新增负向测试固定 waiter 在注册前／挂起后取消均能退出、清空，后续 signal 不会二次
  resume；Danmaku 异常诊断路径也会先释放全部故意非协作的旧请求。
- 普通黄区与红区最终复核均无 blocker；红区结论不替代 App Gate 和远程矩阵。
