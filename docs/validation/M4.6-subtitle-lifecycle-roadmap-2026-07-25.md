# M4.6 字幕生命周期与路线评估验证

> 日期：2026-07-25（Asia/Tokyo）
> 环境：macOS 26.5.2（25F84），Apple Silicon arm64，Xcode 26.6
> 范围：字幕 identity/reset 生命周期、签名生产集成 probe、M5 路线与 v1 截线

## 结论

M4.6 找到一个可确定重现的 A → B → A 缺口：旧 A reset 可以在新 A session 建立后
使 repository generation 失效，界面永久停在字幕正文 loading。本地实现候选改为让
reset 与 load 由单 worker、最早 pending reset 和单一最新 load intent 串行协调；
生产 SwiftUI task 不再等待非协作 reset/content Task。

可控 A → B 旧 cue 迟到测试没有出现 B 被 A 字幕覆盖。真实签名 A → B → A 曾完整
通过一次顺序生产集成，证明当次 context、player timeline 与 subtitle identity 相等，
player timeline generation 前进且最终清理完成；它不制造真实网络竞态，不能替代
确定性 ABA 测试。

截至 2026-07-25，用户观察到的“其他视频字幕”仍未被复现，因此当时只声明修复已证明
的 ABA loading、认证恢复与任务上限问题。后续证据与接口迁移记录见下节。

## 2026-07-26 字幕目录接口迁移

用户随后在只打开一个视频的全新 App 会话中稳定观察到其他内容的字幕。对同一
BVID/CID 的脱敏指纹检查显示 `/x/player/v2` 会在多次请求间返回不同字幕目录和不同
正文资源，而同一正文资源本身没有观察到内容漂移，因此不稳定点位于旧目录接口。

参考项目历史提供了直接对应证据：wiliwili 在 2024-11-05 以
“Temporary fix for subtitle”把目录从 `/x/player/v2` 改为 `/x/player/wbi/v2`；
ATV-Bilibili-demo 在 2024-12-01 记录“疑似被风控导致返回随机字幕”，随后同日把播放
信息接口迁移到 WBI 版本。当前 PiliPlus、wiliwili 和 ATV-Bilibili-demo 均使用
`/x/player/wbi/v2`。

生产实现因此删除基于 cue 时长猜测内容是否匹配的候选方案，改为对 `bvid`、`cid`
进行 WBI 签名后请求 `/x/player/wbi/v2`。认证 allowlist 只接受
`bvid`、`cid`、`wts`、`w_rid` 四个参数；旧 `/x/player/v2` 不再允许携带 Cookie。
签名被 403 拒绝时只刷新一次 WBI key，正文来源策略和字幕 identity/generation
生命周期保持不变。

同日本机签名生产探针使用既有 Keychain 登录态和已知复现样本通过：生产链路取得
2 条字幕轨并到达 `decoder=ready`。探针日志未包含输入 BVID 或凭据字段；构建日志中
仍有 SwiftPM 公开依赖 URL，因此不把“无任何 URL”作为本次日志断言。单次探针只证明
新版接口在当前环境可用，错配是否消失仍需 App 内连续复测。

## 确定性失败与修复

修复前，`SubtitleViewModelTests` 的 A → B 测试通过，但 A → B → A 测试稳定失败：

- 最终状态停在 `.loadingTrack(A)`；
- 当前 cue 为空；
- 旧 reset 在新 A session 建立后使其 cue 请求失效。

初版修复随后由红区审查发现：每次 select 创建的 `contentTask` 会等待同一个
non-cooperative reset，取消不能使 `Task.value` 提前返回，快速切换会累积 waiter。
第二版改为只保留一个最新 load intent；审查进一步发现生产 `VideoDetailColumn`
仍在 SwiftUI `.task(id:)` 中等待 ViewModel worker，因此删除该生产等待。最终复核
没有 lifecycle、pending、generation、认证恢复、timeline owner 或资源上限 blocker。

最终定向覆盖九项：

- 正常 pause/rate/seek cue；
- 关字幕与切轨；
- 新 track/identity 拒绝旧结果；
- A → B 非协作旧 cue 迟到；
- A → B → A stale reset；
- 登出暂停后登录恢复；
- 登出暂停后离页不恢复；
- queued transition 中关闭；
- 空目录、认证失败与 reset 安全状态。

定向套件单次 9/9 通过，并连续重复 25/25 轮通过。

## 签名生产集成

显式 probe 使用一个生产 `AVPlayerEngine`、正式游客内容 repository、正式授权器、
生产字幕 repository/decoder 和两个不同的带字幕公开样本，执行 A → B → A。输入通过
临时 xctestrun 注入；脚本只打印固定 category/summary，不回显 raw line。

成功结果只包含：

```text
sessions=3
context-player-timeline-subtitle=equal
player-timeline-generation=advanced
cleanup=complete
```

同一对样本的额外复跑并不稳定：失败位置曾在 A、B 和返回 A 间变化，其中一次明确为
生产字幕目录为空，也出现过没有命中允许公开分类的失败；相同样本在另一次又完整通过。
这些复跑没有提供串片证据，且失败位置不固定；probe 不观察字幕正文呈现，不能判断
旧 cue 是否覆盖，该隔离结论只来自确定性测试。当前证据不足以区分远端目录、限制、
认证会话、网络瞬态或本地 adapter 失败，故停止继续请求并保留为未解释边界，不将其
归因于串片或本次 ABA 修复。

probe 的 build、test manager、外层进程与 xcresult 解析均有明确时限。所有 raw log、
xctestrun、DerivedData 与 xcresult 位于权限为 0700 的唯一临时目录，并在成功、失败、
中断或超时后删除。验证记录不包含账号、标题、BVID/CID、字幕正文或完整 URL。
