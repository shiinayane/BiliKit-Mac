## 真实分 P 切换补充

- `GuestVideoUseCase.preparePage(in:cid:)` 复用已取得的详情与排序 pages，只通过现有游客
  repository 为目标 CID 重新取得 playurl；列表外 CID 在请求前失败。
- `GuestVideoViewModel` 分离 `requestedPlaybackIdentity` 与
  `presentedPlaybackIdentity`。切换开始即停止旧播放 adapter、撤销旧 presented media，
  generation 与取消共同拒绝 P1 → P2 → P1 的迟到结果。
- 同 BVID 的 loading／failure 不创建新 `PlaybackDestination`；sidebar 目标行分别显示
  loading 或可重试 failure，旧行不继续携带 selected 语义。成功后仍由同一
  `AppWindowOwner`、`AVPlayerEngine` 与 `PlayerHostView` 原位替换 item。
- 分 P 目录沿用已验证 spike 的 plain `List` 结构，最多同时显示 5 行，更多分 P 在目录内
  独立滚动；Disclosure 标题显示总数，行高随 `.callout` 文字尺寸缩放，不以裁出半个第 6 行
  暗示滚动。selected 使用系统 trait；loading、failure 与 retry 状态进入 AX label；hint
  只描述动作，普通行不重复播报“未选择”。
- `VideoPlaybackView` 只在新 identity 进入 preparing／ready 后启动字幕与弹幕；切换准备、
  失败、Back、关窗或 reset 时 identity 归 nil 并清理两条支线。
- 真实 `AVPlayerItem` 在 ready 后异步失败时，engine 立即移除当前 item 并停止 bridge，随后
  通过窄的 `(identity, loadIntent)` 事件通知 ViewModel；只有仍匹配当前 requested identity、
  当前不可复用 intent 且处于 preparing／ready 的事件才能进入 `.failedPage(.playback)`。
  该状态同步清空 presented identity、字幕和弹幕，并允许同 CID retry；adapter item token、
  feature intent 与 generation 共同拒绝旧 item、同 CID ABA 和 `load()` 返回竞争窗口。
- `PlaybackControlling` 不再提供忽略 load intent 或返回空 failure stream 的默认降级；所有
  adapter 与测试 fake 必须显式实现 intent load 和 failure event 契约，遗漏会在编译期暴露。
- 完整 `app` gate 通过：Swift Package 为 236 tests／36 suites 通过（4 个既有非确定性媒体
  timing tests 按契约跳过），App unit tests 包含 post-ready failure、分 P playback failure、
  字幕／弹幕 replacement 与 reset。签名 macOS XCUI
  `testProductionPartSelectionReplacesLocalPlayerItemAndCleansOnBack` 为 1 test／0 failures；7 分 P
  fixture 使用中日英混排长标题，P7 初始不可点击，经生产 `List` 自身 identifier 和实际容器
  高度驱动滚动后可点击；同时观察到 AX selected trait 转移、player identity 不变、item
  identity 替换、generation 增长，以及 Back 后 item／observer／临时媒体目录归零。XCUI 不再依赖
  SwiftUI 当前 `.outline` role 或复制 32 pt 私有布局常数。
- 同一签名 XCUI 在选择 P7 后折叠并重新展开目录，直接以 P7 行与 List 的可见交集确认当前项
  自动回到视区；折叠／展开前后 player identity、item identity 与 generation 均保持不变。
- 原有长 round-trip XCUI 的两次补跑分别停在首窗 resize 与来源 item hittable 前置条件，
  均未进入播放页，分类为 `test.infrastructure`，不作为分 P 产品失败或通过证据。

## Stage 1.1／1.2 历史生产结果

以下记录保留真实分 P 接入前的 merge-time 基线；其中“只读目录”和“不暴露 Button”仅描述

## 独立审查

本次真实分 P 独立 reviewer 首轮发现登出未关闭播放资源、分 P `playback.load` 失败及
字幕／弹幕换代测试缺口，以及新旧文档语义冲突。修复后复核确认这些问题关闭；随后补充发现
ready 后真实 item 异步失败未回传 feature、`load()` 返回竞争窗口、同 CID ABA 迟到 failure，
以及长目录没有第 6 项以后可达的自动化证据。实现现已加入 identity + load intent failure
通路、两个 continuation 驱动的竞争测试与 7 分 P 有界 List XCUI；最终只读复核未发现其他
actionable 问题，也未发现第二个 player／host、导航扩张或 scope creep。

## 用户人工复核清单

请在本次启动的签名开发版中使用真实游客数据检查：

1. 从热门或搜索打开一个多分 P 且简介较长的视频。
2. 确认同一个系统 sidebar 原位变成“简介—分 P—评论尚未接入”，detail 没有重复简介或分 P。
3. 展开／折叠简介和分 P，选择简介文本；播放器画面和时间线不应重置。
4. 用系统 toolbar 隐藏／显示 sidebar，再把窗口从宽布局拖到约 1080×680；播放器仍可观看，
   sidebar 可以独立滚动，内容不覆盖播放器。
5. 使用系统 Back，确认返回原来源及原有草稿／工作集位置。
6. 开启 VoiceOver，检查阅读顺序、disclosure 展开状态、当前分 P selected 播报，以及评论
   unavailable 文案；loading／failure 时不应朗读上一视频的简介或分 P。
7. 开启 Full Keyboard Access，检查 sidebar toggle、Back、简介／分 P disclosure 和播放器
   控制之间的焦点顺序，没有隐藏焦点或焦点陷阱。
8. 若系统启用了 Reduce Motion 或较大文字，再复核折叠、sidebar 显隐和长文本滚动不会造成
   内容丢失或播放器重建。
