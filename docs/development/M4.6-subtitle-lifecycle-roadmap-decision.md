## Goal

M4.6 只完成两个目标：

1. 复现并修复能够由证据证明的字幕 identity／generation／reset 生命周期缺口，
   同时独立判断用户观察到的“其他视频字幕”是否可复现。
2. 根据当前代码与产品价值提出具体 M5 顺序，并明确 v1/v1.1 截线。

## 已确认上下文

- 生产字幕仍由 `SubtitleViewModel`、`BiliSubtitleRepository`、统一播放时间轴和
  SwiftUI `SubtitleOverlayView` 组成；原生字幕没有生产授权。
- 旧实现用不受 owner 管理的 fire-and-forget reset。A → B → A 中，旧 A reset
  可能使新 A repository generation 失效，令界面永久停在 loading。
- 可控 A → B 迟到 cue 没有覆盖当前 B。该结果不能证明用户观察不存在，也不能把
  ABA loading 缺口表述为串片根因。
- M4.5 已合入；其后续测试稳定性修复合入后，`origin/main` 的 macOS 15/26 CI
  已通过。

## Constraints

- 不迁移到原生字幕，不增加 endpoint、认证协议、缓存、持久化、分页状态机、target
  或通用 coordinator。
- 保持 `BiliAPI` 对字幕 URL／授权的所有权、单一播放时间轴和现有 target 边界。
- 并发测试使用可控 latch／continuation 固定迟到与非协作行为；固定墙钟时间不能作为
  正确性同步条件。
- 每个可观察提交点必须匹配当前 `PlaybackItemIdentity` 与 generation，或明确为空。
- reset worker、pending reset、load intent、timeline subscriber 与 content Task
  必须有固定上限；切视频、认证暂停、离开页面和关窗具有明确清理点。
- 验证与记录不包含账号、标题、BVID/CID、字幕正文、完整 URL 或凭据。

## Slice A：字幕生命周期稳定化

覆盖：

- A → B 的旧 cue／旧 timeline 迟到；
- A → B → A 的旧 reset 与新 session 竞争；
- 非协作 cue/reset、关闭与 queued transition；
- 登出暂停、重新登录恢复，以及暂停后离开页面不得恢复。

实现预算：

- 一个 reset worker；
- 至多一个最早 pending reset identity；
- 至多一个最新 load intent；
- 不为每次视频切换创建等待 reset 的内部 Task 或 SwiftUI waiter。

Stop：

- 若 A → B 始终拒绝旧 cue，只修复已确认的 ABA／认证／资源问题，并把串片标为
  未复现。
- 若真实远端返回错误资源且本地无法区分，停止并定义最窄可观察性边界。
- 若必须引入通用 coordinator、原生字幕或新来源契约，返回新的决策价值 Gate。
- 任一 Gate 失败则不合入当前候选，M5 继续保持阻断；不得靠删除失败测试、保留 raw
  真实日志或扩大生产范围绕过。

## Slice B：路线评估

用户选择精简 v1 截线：

- v1：M5.0 当前热门／最后搜索状态保留、M5.1 单一首页来源、M5.2 相关推荐连续观看，
  以及按真实缺口决定的窄播放切片。
- v1.1：只读评论、服务端观看进度写入、独立播放器窗口、mini player、PiP 与其他
  非核心系统能力。

该选择只决定优先级，不确认 M5.0 revision D2，也不授权首页 endpoint、相关推荐、
播放控制、认证写入或其他 M5 代码。
