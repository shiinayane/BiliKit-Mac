# M5.0 日用状态保留：现状与产品边界

> 本文保留 M5.0 已确认的问题、用户结果和资源边界，不指定必须采用的导航、滚动恢复
> 或状态 owner 方案。旧 D1/D2 revision、风险分级和审查记录属于历史输入，不是实现
> 契约；若它们与当前代码、平台能力或真实 UI 结果冲突，以后者为准。

## 当前问题

- 普通 tab 切换会取消热门／搜索请求并清空成功内容，返回时重新请求和显示首次加载。
- 热门和搜索共用 `GuestBrowseViewModel` 的两份窗口内工作集；它不能继续吸收未来个性
  推荐首页。
- 正式 API transport 明确关闭 URL cache；页面工作集、响应缓存、图片缓存、媒体缓存
  和磁盘持久化是不同问题。
- 旧 `AppReturnSnapshot` 只有来源、搜索词和选中项，不能证明用户离开前视图已恢复。
- 图片请求／解码、History 总量和未来个性推荐的登录边界仍未验证。

## 用户结果

- 普通 tab 往返或从视频页返回时，已经成功加载的内容立即可见，不自动重复请求。
- 返回的是用户离开前可识别的视图上下文，而不是仅让某个 item ID 再次可见；具体实现
  需要用真实 UI 路径验证，不能由 anchor、offset 或 snapshot 名称自行证明。
- 刷新是独立、可见的用户意图。刷新期间保留旧内容；失败不能清空仍然可用的同一
  identity 内容，也不能把搜索 A 显示在搜索 B 下。
- route、query、刷新或关闭后的迟到结果不能覆盖当前状态。

## 保留边界

- 当前热门最多一页 50 项；搜索只保留最后一个 query 的一页。
- 当前热门与搜索合计至多一个 active request；取消向下传播，旧结果按 identity 或
  generation 隔离。
- 关窗清理页面工作集和活动请求；页面状态不得持有播放器、Cookie、response body、
  授权 URL、跟踪 URL 或媒体对象。
- 首次修复不顺带增加数据库、通用 Repository cache、图片 pipeline、媒体缓存、后台
  刷新或未来首页 endpoint。

## 实施与验证

先核对原生导航和 SwiftUI 可用的状态恢复能力，再决定 App／Feature owner 与表示方式；
不要从旧自定义 route 或已有 snapshot 反推方案。

确定性测试覆盖请求次数、刷新失败、query／route 替换、迟到隔离、取消和关窗清理。
真实 UI 路径覆盖热门／搜索的 tab 往返、进入视频并返回、用户刷新和窗口尺寸变化。
只有两类证据共同支持时，才能声明 M5.0 行为完成。

图片、History 上限、磁盘恢复和个性推荐分别按真实问题调查，不与本次修复捆绑。

## 完成结果

M5.0 最终使用系统 Tab 与层级导航表达来源和播放页，删除自定义 route、返回 snapshot、
数值滚动 offset 和视频卡片持久 selected 状态。热门、最后搜索与历史分别保留窗口内
工作集和语义滚动位置；系统返回会停止共享播放器，切换来源不会在不可见 Tab 留下播放
destination。

该实现没有增加 endpoint、认证、数据库、Repository cache、图片或媒体 pipeline，也
没有用导航状态替代请求 identity、取消、迟到隔离或 Feature 工作集 owner。

具体测试与真实 UI 边界以当前代码、质量 Gate 和后续 M5.0.1 审计记录为准。本文只保留
问题、用户结果、资源边界和最终责任划分，不作为当前实施队列。
