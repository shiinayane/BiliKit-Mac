# M5.0 日用状态保留：现状与产品边界

> 本文保留 M5.0 已确认的问题、用户结果和资源边界，不指定必须采用的导航、滚动恢复
> 或状态 owner 方案。旧 D1/D2 revision、风险分级和审查记录属于历史输入，不是实现
> 契约；若它们与当前代码、平台能力或真实 UI 结果冲突，以后者为准。

## 当前问题

- 普通 tab 切换会取消热门／搜索请求并清空成功内容，返回时重新请求和显示首次加载。
- 热门和搜索共用 `GuestBrowseViewModel` 的两份窗口内工作集；它不能继续吸收未来个性
  推荐首页。
- 正式 API transport 明确关闭 URL cache；页面工作集、响应缓存、图片缓存、媒体缓存
  和磁盘持久化是不同问题。
- 旧 `AppReturnSnapshot` 只有来源、搜索词和选中项，不能证明用户离开前视图已恢复。
- 图片请求／解码、History 总量和未来个性推荐的登录边界仍未验证。

## 用户结果

- 普通 tab 往返或从视频页返回时，已经成功加载的内容立即可见，不自动重复请求。
- 返回的是用户离开前可识别的视图上下文，而不是仅让某个 item ID 再次可见；具体实现
  需要用真实 UI 路径验证，不能由 anchor、offset 或 snapshot 名称自行证明。
- 刷新是独立、可见的用户意图。刷新期间保留旧内容；失败不能清空仍然可用的同一
  identity 内容，也不能把搜索 A 显示在搜索 B 下。
- route、query、刷新或关闭后的迟到结果不能覆盖当前状态。

## 保留边界

- 当前热门最多一页 50 项；搜索只保留最后一个 query 的一页。
- 当前热门与搜索合计至多一个 active request；取消向下传播，旧结果按 identity 或
  generation 隔离。
- 关窗清理页面工作集和活动请求；页面状态不得持有播放器、Cookie、response body、
  授权 URL、跟踪 URL 或媒体对象。
- 首次修复不顺带增加数据库、通用 Repository cache、图片 pipeline、媒体缓存、后台
  刷新或未来首页 endpoint。

## 实施与验证

先核对原生导航和 SwiftUI 可用的状态恢复能力，再决定 App／Feature owner 与表示方式；
不要从旧自定义 route 或已有 snapshot 反推方案。

确定性测试覆盖请求次数、刷新失败、query／route 替换、迟到隔离、取消和关窗清理。
真实 UI 路径覆盖热门／搜索的 tab 往返、进入视频并返回、用户刷新和窗口尺寸变化。
只有两类证据共同支持时，才能声明 M5.0 行为完成。

图片、History 上限、磁盘恢复和个性推荐分别按真实问题调查，不与本次修复捆绑。

## 2026-07-26 原生导航 revision N2

本 revision 采用 SwiftUI 原生导航表达来源与播放层级：

- macOS 15 `TabView(.sidebarAdaptable)` 的 selection 是搜索／热门／历史三个平级
  来源栏目；每个 Tab 内使用 `NavigationStack(path:)`，播放视频是类型化
  `PlaybackDestination`，系统 back／dismiss 通过当前 Tab 的 path pop 返回；
- 仍只有一个共享播放 path 与播放副作用 owner。非当前 Tab 的 path binding 永远为空；
  切换 Tab 先清空当前播放 path，不能在不可见 Tab 留下第二个 player host；
- 删除 `AppRoute` 和 `AppReturnSnapshot`。App 只在 path identity 变化时启动或停止
  播放副作用，不再保存 Feature 的选中项或列表内容；
- 热门和最后搜索的 presentation 分别读取自己的有界工作集，因此切换 Tab 时非当前栏目
  不再因为共享 active state 而主动移除已加载 Grid；App shell 为热门、搜索和历史
  分别保留一个 `ScrollPosition(idType: String.self)`，Grid 用
  `scrollTargetLayout()` 提供视频 identity，作为窗口内位置的唯一 owner，不再并行
  保存和回放数值 offset；新搜索词和登录身份变化会重置对应位置；
- 仍只有一个 Browse active Task 和 generation。普通激活复用成功工作集；显式刷新
  保留旧内容，失败以附加状态呈现；关窗 `reset` 清空两份工作集。
- 删除视频卡片 API、交互 policy 和辅助功能中的持久 `selected` 分支；hover、press 和
  keyboard focus 反馈保留。

该选择不增加 endpoint、认证、数据库、Repository cache、图片或媒体 pipeline。原生
path 只替代 App 自定义 route；它不替代请求 identity、取消、迟到隔离或 Feature
工作集 owner。

当前实现仍是进行中候选。确定性 Package 测试、App 导航／player host 生命周期测试
与最高适用 App Gate 已通过；本机 unsigned build 的辅助功能树确认原生 Tab sidebar、
底部账号入口和热门／搜索切换可用。旧 offset fallback 的一次受控热门中段往返从滚动条
比例 `0.400` 返回到 `0.349`，暴露了系统保留与手动数值恢复的双 owner；该 fallback
随后由 App shell 持有的原生语义 `ScrollPosition` 取代。只绑定未配置 target 的空
`ScrollPosition()` 也不足以恢复：真实滚动 `0.592` 往返后变成 `0.312`。补上
`idType` 和 `scrollTargetLayout()` 后，两次真实热门往返分别为
`0.195066 → 0.194867`、`0.389877 → 0.389447`，未再发生整行吸顶。先前 fixture
XCUI 仍受 runner 启动环境阻塞。

返回来源页面不保留“上次点开的视频”为选中项，也不绘制持久强调色边框。原生导航栈与
每 Tab 的 `ScrollPosition` 表达返回上下文；继续保留 selected BVID 会把来源提示误解
为正在播放或已观看状态。键盘操作产生的临时系统焦点仍按 macOS 辅助功能语义显示。
