# BiliKit 产品愿景与 v1 截线

> 状态：已接受的 v1 产品结果与范围基线；评论辅助阅读、跨客户端历史连续性等
> v1.1 内容仍是长期方向。本文定义用户价值、优先级和边界，不授权新增 endpoint、
> 认证写操作、持久化 schema 或媒体生产契约；具体实现仍须通过对应决策 Gate、
> 用户确认和验证。

## 产品愿景

BiliKit 的首要目标不是复刻官方客户端的功能数量，也不是堆齐所有 macOS 系统能力，
而是成为一个资源占用可控、导航连续、适合日常观看的原生 Mac 客户端。

长期产品愿景包含评论辅助阅读与跨客户端历史连续性，但 v1 先稳定完成更小的高频
观看闭环：

```text
首页浏览个性推荐视频流
    ↓
进入同窗口视频页
    ↓
观看视频 + 弹幕 + 字幕
    ↓
点击相关推荐，连续切换到下一个视频
    ↓
返回首页并恢复来源上下文
```

这里的“连续切换”描述的是产品体验：App shell 和播放器宿主保持稳定，页面内容按新的
视频 identity 更新；它不意味着采用 Web SPA 技术，也不允许旧视频的详情、媒体、字幕、
弹幕或相关推荐结果回流到新视频。

## 核心体验

### 1. 首页是个性推荐入口

- 本文所称“首页视频流”明确指个性推荐流，不是当前已经实现的“热门”列表。
- “热门”是公共发现入口，可以继续独立存在，但不能改名或静默回退成个性推荐首页；
  推荐来源不可用时必须呈现准确的加载、失败或登录边界。
- 首页产品方向是以单列 `LazyVStack` 承载个性推荐视频卡片流，接近底部自动续载，
  而不是使用当前 History 的底部“加载更多”按钮。
- 首页、搜索和观看历史可以从不同来源打开同一个视频页，但各自保留自己的加载、
  错误、分页和返回语义。
- 普通 tab 往返或从视频页返回时，已经成功加载的工作集应立即恢复，不能重新显示
  首次 loading 或自动重复请求；刷新是独立、可见的用户意图。
- 从视频页返回时，应恢复来源入口、搜索词、选中项和可合理恢复的滚动上下文。

页面工作集保留不等于通用网络缓存。API 响应、图片、媒体和磁盘持久化分别拥有不同的
隐私、资源与失效边界；不能为了消除 tab 重载一次性引入通用 Cache。当前最小方案见
[`M5.0-daily-client-state-retention-decision.md`](../development/M5.0-daily-client-state-retention-decision.md)。

`LazyVStack` 只解决 View 的惰性创建，不自动解决分页正确性、列表增长、图片内存、
重复请求或滚动恢复。这些具体方案不在本文预定，由 M5.1 独立来源契约制定。

#### App 端与 Web 端首页来源比较

从既有 userscript 使用经验看，Bilibili 同时存在 App 端与 Web 端的首页体验。它们应
作为两个待比较候选；不能因为字段相近就假设推荐语义、登录边界或分页协议相同，也
不默认同时接入生产。M5.1 先完成最低成本结构比较，最终只选择一个生产来源。

### 2. 视频页是观看工作区

- 播放器是稳定主锚点；字幕、弹幕、分 P 和相关推荐围绕它工作。
- 视频、字幕和弹幕共享唯一播放 identity 与时间轴。
- 点击相关推荐时保持同一窗口和单一播放器 host，同时取消旧视频拥有的异步任务与
  媒体资源。

### 3. v1.1 扩展观看工作区与跨设备连续性

- 只读评论是后续阅读辅助区；加载、分页、失败或登录限制不能中断当前播放。
- 当前只读 History 不能证明 BiliKit 内的观看已经写入服务端。
- v1.1 可评估让登录用户的受控观看进度进入服务端历史，使 BiliKit 与其他客户端形成
  连续体验。
- 进度上报属于认证写操作和观看隐私红区，必须单独明确上报时机、频率、失败语义、
  登出清理、日志脱敏和真实账号验证；游客路径不得发送认证写请求。

## v1 优先级与截线

v1 必须优先保证：

1. 首页个性推荐流可以稳定刷新、进入视频页并返回；普通导航不重复加载，现有“热门”
   不充当完成证据。
2. 视频播放、seek、字幕和弹幕在连续切换后保持正确。
3. 相关推荐支持 A → B → C 的同窗口连续观看，并隔离旧结果。
4. 只为真实日用播放缺口增加最窄控制能力，不创建第二播放器或第二时间轴。
5. 上述路径具有基本键盘可达性、辅助功能语义和目标窗口尺寸下的稳定布局。

以下能力有价值，但不阻塞 v1 核心闭环，可作为 v1.1 候选：

- 独立播放器窗口、mini player 和画中画。
- 拖入视频 URL、系统分享、完整 Commands 和媒体键集成。
- 为低频模式增加的窗口恢复或高级工作区定制。
- 只读评论。
- 服务端观看进度写入与历史闭环。

下载、转码、媒体导出、直播、多账号、区域解锁，以及评论、关注、收藏、稍后再看等
社交或 Library 写操作不属于这条 v1 核心闭环。

## 路线图含义

- M4.6 先稳定字幕生命周期并完成路线评估；未复现的串片观察不写成已修复事实。
- 随后先关闭 M5.0 当前热门／最后搜索的内存工作集保留，再由 M5.1 完成 App／Web
  首页来源对照与单一来源选择，然后实现 M5.2 相关推荐连续观看。
- 播放控制只按真实缺口进入窄切片。评论、服务端历史写入、画中画和 mini player
  后移至 v1.1；它们不能替代 v1 核心观看闭环的完成证据。
- 后续红区审查可以依据风险与依赖重排尚未开始的切片，但不得把本文当作生产授权。
