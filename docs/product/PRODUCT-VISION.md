# BiliKit 产品愿景与 V1 截线

状态：已接受的产品结果；当前实现状态以 `ROADMAP.md`、代码和发布 Gate 为准

## 产品定位

BiliKit 是为 Mac 设计的原生、克制、非官方 B 站浏览与播放客户端。它不追求复制网页全部功能，
而是让发现内容、进入视频、连续观看和返回来源发生在一个稳定的 Mac 窗口体验中。

首页个性推荐与热门是不同语义的入口；搜索与观看历史保留各自工作集。它们进入同一个视频工作区，
但返回时仍恢复真实来源上下文，而不是把所有页面压成一份全局路由或通用缓存。

## V1 核心结果

- 首页个性推荐能够刷新、分页、失败重试并与热门保持独立；
- 热门、搜索和观看历史能够进入视频页并恢复来源工作集；
- 单一 player host 支持连续 A → B → C 播放，不创建第二播放器或第二时间轴；
- 自动画质、seek、倍速、字幕、弹幕、分 P 和语义音轨在 identity 替换后保持一致；
- 只读评论与相关推荐围绕播放器工作，加载和失败不能中断当前媒体；
- 登录播放自动同步服务端观看进度，使正常观看及时进入观看历史；该能力默认存在且不提供开关，
  但游客、凭据故障与远端拒绝仍保持播放完全可用；
- 登录凭据只进入短生命周期内存与 Keychain，游客和媒体链路不继承认证；
- 核心路径具有真实用户需要的键盘和辅助功能语义；build、AX tree 和截图不能替代真人验证；
- 通过 Developer ID 签名、公证和 Gatekeeper 验证的 Universal DMG 提供可重复安装与恢复路径。

页面工作集不等于网络缓存。API 响应、图片、媒体、UserDefaults、Keychain 和未来持久化分别拥有
独立的隐私、容量、失效与清理边界；不能为减少一次加载引入通用 Cache、数据库或 Shared Store。

## V1 截线

V1 不包含下载、转码、导出、直播、多账号、区域解锁、DRM 绕过、评论写入、关注、收藏或稍后再看。
服务端观看进度是 V1 唯一认证写操作，只服务“正常播放进入观看历史”，不能扩展为通用互动写能力。
实验播放线路和 macOS 26 响度均一化不构成稳定可用性承诺。

站外自动更新不是“能下载文件”就完成。只有不含更新器的 Developer ID 基线通过后，才允许按独立
安全 Gate 接入 Sparkle；不自研替换器，不让更新网络接触 Bilibili 用户凭据。

## 后续方向

独立播放器窗口、高级工作区定制和观看进度以外的写操作都需要新的用户结果、隐私边界与真实接口
证据。它们不是 V1 完成条件，也不能以预留 target、占位 UI 或未调用 abstraction 提前进入工程。

任何范围变化先更新本文，再进入候选登记或路线图；旧研究、阶段计划和审计记录不能自动授权实施。
