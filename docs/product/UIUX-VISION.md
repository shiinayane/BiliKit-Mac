# BiliKit App UI/UX 产品蓝图

状态：长期界面方向；已实现事实以当前 App 和 `ROADMAP.md` 为准

## 整体信息架构

- 系统侧栏承载首页、热门、搜索和观看历史；每个入口保持自己的内容语义、状态与滚动上下文。
- 首页是个性推荐，不由热门数据冒充；推荐不可用时呈现准确的加载、失败或登录边界。
- 视频页在同一窗口进入层级导航，返回恢复来源；同一视频内切换分 P 不增加导航层级。
- 界面使用系统窗口、侧栏、toolbar、focus、菜单和辅助功能行为，不复制网页导航或播放器控制条。

## 浏览页面

- 首页推荐、热门、搜索和历史共享响应式 16:9 视频卡片语言，但不共享一份可互相污染的页面状态。
- 刷新是明确的用户意图；刷新期间可保留同 identity 的旧内容，失败不清空仍可用结果。
- 分页追加有明确上限、加载尾和重试；窗口切换、搜索词变化和账户 generation 变化必须隔离迟到结果。
- 卡片选择、键盘 focus、VoiceOver 分组和滚动恢复服务真实用户，不以 accessibility label 充当测试 ID。

## 视频工作区

- 播放器是主区稳定锚点；标题、元信息、字幕、弹幕、相关推荐和侧栏阅读围绕同一媒体 identity。
- 窄窗口优先保证播放器可观看宽度，系统侧栏可以收起；resize、全屏、PiP、返回和媒体替换不得复制
  或重建第二个 player host。
- 多分 P 目录诚实区分当前、加载、失败和重试，并在重新展开时定位当前项。
- 相关推荐位于 detail 下方的横向 shelf，不自动播放、不无限循环，不跨过侧栏分隔线。

## 评论阅读

- 播放侧栏以单一 AppKit scroll owner 组织简介、分 P 和只读评论；评论分页、图片、文本选择和楼中楼
  不重建或控制播放器。
- 评论失败、受限或缺少数据时显示准确状态，不伪造内容、不以登录诱导代替错误。
- 外链只在用户明确点击后，由严格解析边界交给 App 内导航或系统浏览器；不预取未知目标。
- 评论写入、关注、收藏等写操作不属于当前蓝图的已授权能力。

## 输入与辅助功能

- 优先采用系统播放器控制、菜单、按钮、列表和焦点行为；BiliKit 特有 action 必须有明确用户结果，
  不能仅因 API 存在就增加浮层。
- 触控板纵向滚动、播放器横向手势、控制条、全屏和页面滚动之间的冲突需要单独真实收口。
- VoiceOver、Full Keyboard Access、动态文字和高对比度必须真人验证；截图、固定坐标和内部视图层级
  不构成验收。

## 演进规则

新页面、写操作、持久化 schema 或自定义播放器 UI 必须先说明它解决的真实空白、失败时页面是否仍
成立、owner 与清理点，以及为什么值得增加状态和维护成本。候选位置不等于接口或实现授权。
