# 产品候选登记

> 本表保存已经确认值得继续处理、但尚未成为当前实施阶段的事项。条目没有优先级和版本
> 承诺，也不授权 endpoint、凭据、持久化或生产改动。开始实施前必须根据当前外部事实、
> 风险与成本重新裁决；被选中的唯一下一阶段再进入 `ROADMAP.md`。

| 候选 | 期望的用户结果 | 进入实施前的边界 |
| --- | --- | --- |
| 登录态自动画质 | 登录用户可以在服务端实际授权范围内获得更高画质，同时继续由单一 `AVPlayerItem` 原生 ABR 自动选择 | 作为独立安全 Stage，从最小真实请求重新验证 Cookie、WBI、风控、allowlist、redirect 和可用 representation；不得恢复已回退的 412 实验或宣称保证 4K |
| 播放器区域纵向滚动 | 指针位于视频上方时，触控板纵向滑动仍滚动整个详情页，不被解释为 seek | 保持原生控制条、全屏、横向手势和辅助功能可用；只解决已确认的纵向冲突 |
| 播放器浮动 action | 在不替换原生播放控制条的前提下，为 BiliKit 特有的播放操作提供易发现的浮动入口 | 实施前确定具体 action、位置、显隐和点击反馈；不能把 `AVPlayerView.controlsStyle = .floating` 当成该产品结果已经实现 |
| 个性推荐首页 | 提供与热门语义不同的个性推荐入口，并复用当前响应式视频网格进入和返回播放页 | 立项后再选择单一真实来源并验证登录、失败、刷新、分页、取消和有界工作集 |
| 相关推荐连续观看 | 在同一窗口和单一 player host 中从当前视频继续观看相关视频 | 新 identity 必须取消并隔离旧详情、媒体、字幕、弹幕和推荐结果，返回仍恢复原来源上下文 |
| v1 发布准备 | 对实际采用的交付方式形成可重复的构建、签名、安装与运行结果 | 不走 Mac App Store；在 Developer ID 公证打包与 v1 不打包之间裁决后再建立对应流程 |

详细审计事实和当时裁决保留在 [`../audits/M5.0.1/`](../audits/M5.0.1/)；本表只保存
不会因审计阶段结束而丢失的产品结果，不替代其证据边界。
